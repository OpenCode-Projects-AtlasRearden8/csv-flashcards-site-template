# STATUS — csv-flashcards-site

## What was built

A static template that turns any CSV of terms into a friendly study site,
generated by a stdlib Python build script. Python 3.8+ standard library
only; no dependencies for the build.

- `build.py` — reads every `*.csv` in `data/` (row 1 = headers naming the
  card front/back; extra columns ignored), escapes and embeds the decks as
  JSON, and renders `templates/index.html` (study page) and
  `templates/print.html` (no-frills print sheet) into `site/`.
- `templates/index.html` — two-sided flip cards (CSS 3D), shuffle +
  original-order buttons, reverse mode (back first), know / don't-know
  sorting with a "study not-yet cards" queue and live counts, multi-deck
  picker, keyboard shortcuts (Space flip, arrows, K, N), reset marks.
  All data is embedded inline — the page works offline from `file://`.
- `templates/print.html` — plain table of every card with rows, checkbox
  column, sections per deck; print-friendly CSS.
- `data/ai-basics.csv`, `data/healthcare-study.csv` — two sample decks
  (18 cards) demonstrating the format.
- `tests/test_build.py` — 19 pytest tests: output structure, deck naming
  and header labels, multi-deck indexing, HTML/JS escaping of adversarial
  content, blank-row tolerance, Unicode round-trip, deterministic output,
  custom titles, clean error messages for empty/broken CSVs, sample-data
  build, and LICENSE/README content.
- `LICENSE` — MIT, `Copyright (c) 2026 Asdale Dynamics, LLC`.
- `README.md` — quick start, CSV format, features, GitHub Pages steps,
  tests, credit to Asdale Dynamics, LLC (complements the scoring-focused
  vocab-quiz-builder-cli; this one is free-recall flashcards).

## How to run it

```sh
python3 build.py                      # data/ -> site/
python3 build.py --title "My Cards"   # optional title
python3 -m pytest tests               # run the test suite
```

Open `site/index.html` in a browser (double-click works — it runs from
`file://`). For GitHub Pages, commit the repo and point Pages at the
branch/folder containing `site/` (e.g. move it to `docs/`).

## Known gaps

- Card marks are kept in page state only (no localStorage), so a refresh
  clears the know / not-yet lists by design — no data written to disk.
- Deck-`reverse` toggle is global per session; per-deck default is not
  configurable.
- Only UTF-8 CSVs; no TSV/Excel ingest.
- Extra CSV columns are silently ignored (a warning could help).
- Print sheet styling is intentionally plain; no folded flashcard layout.
