# CSV Flashcards Site

A static template that turns any CSV of terms into a friendly study site:
two-sided flip cards, shuffle and reverse modes, know / don't-know sorting,
and a no-frills print sheet. Generated by a standard-library Python build
from the CSV headers it reads — no JavaScript editing needed.

The generated site is fully self-contained, runs offline straight from
`file://`, and is GitHub Pages ready.

## Quick start

1. Put one or more CSV decks in the `data/` folder (see format below).
2. Build the site:

   ```sh
   python3 build.py
   ```

3. Open `site/index.html` in any browser. That's it — no server, no install.

Options if you want them:

```sh
python3 build.py --data-dir data --out-dir site --title "My Study Cards"
```

## CSV format

Row 1 is the header row: the first two columns name the card's **front**
and **back** sides. The filename becomes the deck name. Extra columns are
ignored; extra rows in other formats are skipped with a warning.

```csv
Term,Definition
Prompt,A question or instruction you give an AI to get a response
Hallucination,When an AI makes something up and states it confidently
```

One CSV per deck. Any content is fine — Unicode, quotes, commas inside
cells. The build escapes everything, so odd content can't break the page.

## What the built site does

- **Flip cards**: click a card (or press Space) to flip it front-to-back,
  with CSS 3D animation. Arrow keys move between cards.
- **Shuffle** reshuffles the deck into a random order; **Original order**
  restores the CSV order.
- **Reverse mode** swaps the sides, so you can quiz yourself from the backs.
- **Know it / Not yet**: marked cards are sorted into two lists with a live
  count. "Study 'not yet' cards" reviews only your miss pile. Keyboard
  shortcuts: `K` for know, `N` for not yet.
- **Print sheet**: `print.html` lists every card in a plain table with a
  checkbox column — handy for cutting into paper flashcards. Link to it
  from the header of the study page.
- **Multiple decks**: every CSV in `data/` becomes a deck with a picker on
  the page; marks are per deck.

## Hosting on GitHub Pages

1. Commit the repository (the generated `site/` folder can be committed, or
   rebuilt at deploy time with `python3 build.py`).
2. In your repo settings, set GitHub Pages to serve from the branch/folder
   containing `site/` (for example, move it to `docs/`, or configure Pages
   with the custom folder your CI produces).
3. Done: `https://<user>.github.io/<repo>/site/index.html`.

No build steps, package managers, or JavaScript edits are required on the
hosting side.

## Running the tests

```sh
python3 -m pytest tests
```

The tests build throwaway sites from temporary CSVs and assert on the
generated files — structure, escaping, multi-deck behavior, error handling,
and deterministic output.
